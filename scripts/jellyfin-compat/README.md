# Jellyfin differential harness

This harness runs one bounded HTTP manifest against Jellyfin 10.11.11 and Rivune. It records differences; it does not certify general Jellyfin or media-player compatibility.

## Requirements

- Bash, `curl`, `jq`, Go, and `sha256sum` or `shasum`;
- Docker with Compose v2;
- a running Rivune instance with a compatible profile and a movie named `Rivune Demo`.

The oracle is pinned to `jellyfin/jellyfin:10.11.11@sha256:aefb67e6a7ff1debdd154a78a7bbb780fd0c873d8639210a7f6a2016ad2b35db`, exposed only on `127.0.0.1:18096`, and destroyed with its disposable volumes after each run.

## Run

```sh
cp scripts/jellyfin-compat/targets.env.example scripts/jellyfin-compat/targets.env
chmod 600 scripts/jellyfin-compat/targets.env
# replace every example value
scripts/jellyfin-compat/run.sh
```

`targets.env` is ignored by Git and loaded as trusted Bash. The harness rejects symlinks and group/world-readable files. Never put secrets in command arguments or committed artifacts.

The run verifies the synthetic asset digests in `NOTICE`, starts and bootstraps the oracle, validates the manifest, executes both targets, compares artifacts, and removes the oracle even after failure. Results go to a new timestamped directory under `work/runs/` unless `JFCOMPAT_OUT_DIR` selects another unused path.

Core commands are also available from `server/`:

```sh
go run ./cmd/jellyfin-compat validate -manifest ../scripts/jellyfin-compat/requests.json
go run ./cmd/jellyfin-compat run -manifest ../scripts/jellyfin-compat/requests.json -target upstream=http://127.0.0.1:18096 -target rivune=http://127.0.0.1:8080 -out ../scripts/jellyfin-compat/work/manual
go run ./cmd/jellyfin-compat compare -left ../scripts/jellyfin-compat/work/manual/upstream -right ../scripts/jellyfin-compat/work/manual/rivune -out ../scripts/jellyfin-compat/work/manual/diff
```

## Scope

The manifest covers public identity, authentication, current user, views, items, search, artwork headers, `PlaybackInfo`, and logout. Ten steps compare normalized semantics; logout compares exactly. Deployment-dependent artwork remains an explicit observed gap rather than a skip.

The manifest stops at `PlaybackInfo` because the targets do not share source IDs, delivery URLs, or transcoding decisions. Capturing unrelated successful stream responses would not prove decoded media, seeking, or lifecycle behavior. Generated byte-path tests and real-client promotion rules are documented in [Jellyfin compatibility evidence](../../docs/jellyfin-compatibility.md).

Synthetic MP4, VTT, and SVG inputs come only from `server/internal/demo/assets` and are documented in `NOTICE`. Docker may pull the separate GPL Jellyfin oracle; the harness copies no Jellyfin code or third-party media.
