# Jellyfin 10.11.11 Compatibility

## Scope, baseline, and evidence level

This document describes Rivune's compatibility surface as **observed in the repository's code and tests**. It does not certify compatibility with any client. In particular, the presence of a route, a dispatch test, an HTTP 2xx response, or DTO similarity proves neither parity with Jellyfin nor a complete Infuse, VidHub, or Streamyfin workflow.

### Legend

- **Request**: `E` = understood and bounded submitted subset; `P` = partial parameters or precedence rules; `M` = minimal input; `S` = probe/stub route, input accepted but functionality absent.
- **Response**: `E` = useful and tested local shape; `P` = partial DTO/fields; `M` = conservative/minimal value; `S` = intentionally empty container, `false`, or 204.
- **Function**: `F` = projected function actually executed; `M` = minimal shim/no-op; `S` = honest stub.
- **Status**: `✅ local` = tested Rivune contract, **not** Jellyfin parity or client validation; `🟡 partial` = known gap or reduced function; `🔴 gap` = observed incompatible behavior. An `S` row is always `🟡 partial`, never `✅`.
- **Clients**: `A` common bootstrap, `B` navigation/catalog, `P` playback, `T` playback state. All are **[INFERENCE]**, except `G`, which denotes the synthetic Generic A/B/C clients used in tests. `SF` indicates an endpoint actually read in the Streamyfin source, and `ARVIO` indicates the pinned ARVIO request sequence reproduced by local HTTP tests; neither code means a successful application workflow against Rivune. No client code means “client validated.”
- **Tests**: `U` exhaustive root + `/emby` dispatch and installation; `O` local route/OpenAPI parity; `D` discovery/auth; `B` bootstrap; `C` catalog; `CS` catalog surface; `I` artwork; `P` playback; `T` state; `Q` synthetic HTTP sequences. `U,O` alone prove presence, not semantics.

The 122 rows below cover exactly `routeDefinitions` in `server/internal/jellyfin/routes.go`. Numbering 1–115 is retained for historical routes, and routes added since then are recorded at the end of the table; row order therefore no longer matches source order. Each route also accepts the exact `/emby` prefix; this variant is not an additional RouteSpec.

### Dolby Vision: evidence boundaries

- **Metadata — PASSED locally**: the `dvh1` tag or FFprobe side data `DOVI configuration record` becomes `DOVI`/`dolby_vision`; this test parses neither the Dolby Vision profile nor the RPU.
- **Direct play — ABSENT**: no authorized Dolby Vision fixture is decoded or sent to a player. A DeviceProfile decision is not evidence.
- **Base layer — ABSENT**: no extraction, HDR10/SDR preservation, pixel comparison, or synchronization validation is present.
- **Tone-map — ABSENT**: the decision boolean and FFmpeg filter construction prove neither execution, colorimetry, nor absence of residual metadata. Promotion requires synthetic or redistributable media with explicit provenance and an assertion on the output; no third-party media may be downloaded to fill this gap.

The HTTP differential smoke test is not extended to these cells: its targets do not currently share a source identifier and canonical delivery URL allowing an identical, bounded media fetch. The optional tests above are the small, local extension: synthetic server, generated bytes, timeouts, and temporary directories. Adding an arbitrary GET to `requests.json` would provide only a deployment-dependent `2xx` and would be false evidence.

## Differential evidence method

The status of each cell must change only through one of the following forms of evidence, from weakest to strongest:

1. **Presence**: `routeDefinitions` and parity with the Rivune OpenAPI (`U,O`).
2. **Local contract**: handler test verifying status, headers, body/fields, side effect, and errors; a fake 204 qualifies only routing/authority.
3. **10.11.11 oracle**: same request executed against the pinned image and Rivune with the same synthetic assets; comparison of statuses, content types, contractual headers, JSON types/nullability/fields, and invariants.
4. **Media workflow**: PlaybackInfo → emitted URL → master/main/init/segments or stream/range → start/progress/stop, with real FFmpeg and synthetic bytes.
5. **Named consumer**: scrubbed trace from a pinned client version, replayed by the harness; only this level permits a claim limited to that workflow and version.

The harness must normalize only explicitly nondeterministic values: IDs/tokens/timestamps, host URL, and documented non-contractual ordering. It must not remove fields, convert `null` into absence, arbitrarily sort semantic lists, accept a different status, or hide a cache/auth header. Each normalization carries a JSON pointer and a reason and is applied separately to each target. Captures are isolated by target; no token, password, provider URL, or secret header is persisted in snapshots, errors, or logs.

Milestone contract commands:

```text
go run ./cmd/jellyfin-compat validate -manifest ../scripts/jellyfin-compat/requests.json
go run ./cmd/jellyfin-compat run -manifest ../scripts/jellyfin-compat/requests.json -target upstream=URL -target rivune=URL -out DIR
go run ./cmd/jellyfin-compat compare -left DIR/upstream -right DIR/rivune -out DIR/diff
```

The baseline is accepted only if the manifest is valid, both executions finish without persisting secrets, and the comparator then produces an explicit diff. A documented `observedGap` may retain an expected gap; it never turns that gap into parity.

The archived smoke ran all 11 captures through the comparator. Its `recompare/summary.json` records `compared=11`, `matched=9`, `skipped=[]`, and two differing steps. For `system-endpoint`, upstream returns an empty 401 (`Content-Length: 0`) without cache, content type, or authentication challenge, while Rivune returns its canonical no-store JSON error with `Content-Type: application/json; charset=utf-8` and `WWW-Authenticate: MediaBrowser`; the summary records every resulting header, body-kind, and JSON mismatch. `user-views` has `/Items/0/ChildCount` equal to `9` upstream and `1` in Rivune. Logout is the one exact comparison. The current manifest likewise declares ten `compare: semantic` steps and one `compare: exact` step, with no `compare: per-target` mode. Artwork `HEAD` remains an explicit `status: observed-gap` because target-local provider availability may differ, but it is still semantically compared and is not treated as parity.

## Performance and security notes

### Performance

- Ordinary `/Items` and `/Items/Latest` accept limits up to 1008 and assemble responses through internal pages capped at 200.
- `Path`, `MediaSources`, and other optional general fields are field-gated; they are no longer synthesized when not requested.
- Sorted collection resolution may still traverse up to 200 000 entries per folder before returning a bounded window; resolutions are parallelized in batches of at most 8.
- PlaybackInfo may sequentially open/probe up to 15 sources, 15 s each in the initial worst case.
- `directorySize` traverses the HLS workspace under a mutex at admission and then periodically; cost grows with jobs × files.
- The local HLS playlist is sliding and bounded at 120 segments with deletion; child capabilities rotate within a tested bound.
- Converted subtitles may be buffered up to 16 MiB; probe data up to 4 MiB. The limits are useful but do not constitute a benchmark.
- Three deterministic, bounded microbenchmarks cover `rewritePlaylist` (8 and 120 references), `directorySize` (32 files of 4 KiB), and the four `direct`/`remux`/`transcode_audio`/`transcode` decisions: `cd server && go test ./internal/playback -run '^$' -bench '^(BenchmarkRewritePlaylist|BenchmarkDirectorySize|BenchmarkPlaybackDecision)$' -benchmem`. They provide comparable measurements on an identified machine; no threshold, p95 budget, global allocation profile, or Jellyfin soak is defined. Any product extrapolation remains an **[INFERENCE]**.

### Security

- Identity boundary: compatibility token bound to the active profile; a foreign UserId becomes 404. Opaque 32-byte tokens are stored only as hashes.
- Disabling the facade revokes all active compatibility sessions; re-enabling must complete revocation of the previous generation before publication. A failure blocks the transition.
- Upstream credentials, provider URLs/headers, and sourceRef remain internal. Child URLs use a PlaySessionId bearer bound to owner/item/source/TTL; HTTPS remains mandatory.
- Playback verifies owner, item, source, and session; FFmpeg targets pass through a signed local gateway with SSRF, redirect, and protocol controls.
- Bodies, queries, profiles, playlists, ffprobe outputs, subtitles, sessions, and sockets are bounded and fail closed.
- Identical authentications are coalesced; distinct operations, artwork fetches, temporary files, and transformations have concurrent quotas and reject on saturation.
- A registered opaque artwork tag authorizes anonymous GET/HEAD of its projected bytes; tagless requests return 401, and unknown, stale, mismatched, or foreign tags fail closed. An explicitly invalid credential cannot be bypassed by a valid tag.
- The socket revalidates the token and bounds leases/messages; its local notifications remain a functional subset, not Jellyfin parity.
- AGPL/GPL/MPL references were observed only to specify behaviors. No code, substantive test, expressive DTO table, or fixture under those licenses may be copied into the Apache-2.0 implementation.

## Limitations of this matrix

This matrix is evidence-backed at the repository level and by the cited external sources. The archived oracle smoke compares all 11 targeted captures: nine match under the manifest's documented semantic normalization, `skipped` is empty, and logout is the one exact comparison. `system-endpoint` differs because upstream returns an empty 401 without cache, content type, or challenge headers while Rivune returns its canonical no-store JSON error with `WWW-Authenticate: MediaBrowser`; `user-views` differs at `/Items/0/ChildCount` (`9` upstream, `1` Rivune). The current manifest has ten semantic modes plus one exact mode; its semantically compared artwork `HEAD` step remains an explicit observed gap rather than a false equivalence. Runtime HTTP golden files and real FFmpeg scenarios are local Rivune contracts, never claims of being “identical to Jellyfin.”
